# MarginGuard

Сфотографируйте накладную поставщика и за секунды увидите, что подорожало, насколько просела маржа, какие цены на полке пора поднять и сколько вы теряете на закупках без НДС-зачёта.

Хакатон Zhambyl Hub, трек «AI for SME & Local Business». Команда: Sami (lead), Bekzat.

> **ДЕМО-ДАННЫЕ.** При первом запуске загружается вымышленный магазин «Хозтовары (ДЕМО)» с 4 вымышленными поставщиками и историей закупок за май–сентябрь 2026. Реальных клиентов у нас пока нет.

## Запуск одной командой

Нужен Python 3.11+. Интернет нужен только при первой установке пакетов. Демо-режим работает без интернета и без ключей.

| ОС | Команда |
|---|---|
| macOS / Linux | `./run.sh` |
| Windows | двойной клик по `run.bat` |

Откройте http://localhost:8000. С телефона в той же Wi-Fi: `http://<IP компьютера>:8000`.

Тесты: `.venv/bin/python -m pytest -q` (Windows: `.venv\Scripts\python -m pytest -q`).

## Сценарий за 1 минуту

1. **Накладная** → «Демо-накладные» → «Оптбаза, фото под углом» → **Загрузить**.-
2. **Проверка**: проверка сумм находит ошибку в строке 3 (цена краски прочитана как 6 220, на бумаге 6 720). Исправьте цену, баннер станет зелёным → **Подтвердить**.
3. **Изменения**: 7 позиций подорожали, маржа просела, рекомендуемые цены, потери ₸/мес.
4. **Поставщики**: у кого есть НДС-зачёт, кто поднимает цены быстрее рынка.
5. **Режим/НДС**: оборот против порога НДС и лимита упрощёнки, со ссылками на источники.
6. **Цены**: отметить, применить, распечатать ценники или скачать CSV.

## Движки распознавания

| Движок | Когда работает | Как включить |
|---|---|---|
| ДЕМО-эталон | только файлы из `demo_data/invoices` (узнаёт их по SHA-256) | всегда включён, в UI помечен «ДЕМО» |
| Claude Vision | любые фото и PDF | `ANTHROPIC_API_KEY=...` в `.env` |
| Локальный OCR | фото, без интернета, качество ниже | `pip install pytesseract` и программа Tesseract с языком `rus` (или PaddleOCR) |
| PDF с текстовым слоем | PDF, где текст можно выделить | всегда включён |
| Ручной ввод | если ничего не распозналось | всегда доступен |

Если движок сменился на запасной, на экране проверки появляется баннер с причиной. Тихой подмены нет.

## Свои данные

Настройки → «Начать со своими данными», затем импорт CSV:

- прайс-лист: `name, unit, category, shelf_price, monthly_units, max_markup_pct`;
- продажи: `month (ГГГГ-ММ), product, units, revenue`.

Разделитель `,` или `;`, кодировка UTF-8 или Windows-1251. Примеры лежат в `demo_data/catalog.csv` и `demo_data/sales.csv`.

## Как считаем

Все формулы лежат в `app/domain/` (чистые функции, покрыты тестами). Все налоговые числа берутся из `config/tax_params_2026.json`, у каждого есть источник и дата проверки.

- Себестоимость. ОУР: у плательщика НДС с ЭСФ берём цену без НДС, у остальных всю сумму. СНР: всегда всю сумму.
- Маржа. ОУР: `(P/(1+v) − cost) / (P/(1+v))`. СНР: `(P(1−t) − cost) / P`. Считается до подоходного налога и накладных расходов.
- Рекомендуемая цена. ОУР: `cost/(1−m)·(1+v)`. СНР: `cost/(1−t−m)`. Округляется вверх до шага и не превышает `max_markup_pct`.
- Утечка НДС-зачёта (сценарий «что если»): `закупки без зачёта × v/(1+v)`.
- Потери в месяц: `рост себестоимости за единицу × продажи в месяц`. Без данных о продажах потери не считаются.

Это инструмент оценки, а не налоговая консультация.

## Структура

```
app/domain       чистая логика: цены, маржа, рост, НДС
app/extraction   схема, проверки сумм, сопоставление, движки, пайплайн
app/web          FastAPI, шаблоны Jinja2, стили, htmx и Chart.js лежат локально
config/          tax_params_2026.json (источники), app_settings.json (пороги)
demo_data/       generate.py, накладные, эталоны, каталог, продажи (всё ДЕМО)
docs/            спецификация, питч, материалы для валидации
tests/           pytest
```

Данные хранятся локально в `data/marginguard.db` (SQLite). Ключи хранятся только в `.env`. Содержимое документов в лог не пишется.
